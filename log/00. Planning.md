# Dzikr & Dua Web App: Architecture Brief

## The Core Concept
A fully client-side web application for listening to Dzikr and Dua.
- **No Database, No Auth:** Users don't log in; all data is local or served via static files.
- **Stateless Sharing:** Playlists and queues are shared entirely via the URL.
- **Continuous Playback:** Audio must not stop or skip when navigating between pages.

## Quick Start Setup
The project is bootstrapped using **TanStack Start** and pre-configured with **shadcn/ui (Radix)** using the following preset command:
`npx shadcn@latest init --preset b4OXsXH05 --template start`

## The Tech Stack
Optimized for a database-less media player, prioritizing client-side speed and strict URL management.

- **Framework & Routing:** [TanStack Start](https://tanstack.com/start)
  - **Why:** Combines Vite's speed with TanStack Router's type-safe URL management. Since there's no database, the URL is our primary state sync mechanism.
- **State Management:** [Zustand](https://github.com/pmndrs/zustand)
  - **Why:** Tiny global state manager that allows the UI and the global audio queue to communicate seamlessly without deep prop drilling.
- **UI Components:** [Radix UI](https://www.radix-ui.com/) (via shadcn/ui)
  - **Why:** Handles complex accessible primitives (sliders, progress bars) so we can focus on the CSS/Aesthetics.

## Core Mechanics & Data Flow

### 1. Audio Persistence
To prevent audio from stopping during navigation, the core media player component (containing the `<audio>` tag) is mounted inside the `src/routes/__root.tsx` layout. As the user navigates, the router only swaps out the nested child pages. The root layout never unmounts, keeping the audio alive.

### 2. URL-Based Playlists (Sharing)
When a user builds a playlist, the app syncs the queue to the URL search parameters (e.g., `?queue=dua-1,dua-4,dua-12`).
- **Validation:** TanStack Router intercepts the URL on load, validates audio IDs against local data, and populates the Zustand store.
- **Optimization:** For large playlists, the array will be compressed into a short string using `lz-string` before updating the URL.

### 3. Decoupled Audio State
The UI and the Audio Player do not communicate directly:
1. User clicks "Play" on a Dua.
2. UI component updates the Zustand store: `setNowPlaying(id)`.
3. The root Audio Player component (listening to Zustand) detects the change, fetches the file, and plays it.
