# 02. Implementation Log

## Overview
This document logs the core implementation steps and technical decisions made during the development of the Dzikr & Dua Web Player, following the grand plan. The application is built as a stateless, continuous-playback media player using TanStack Start, Zustand, and Orama.

## 1. Data Integration
- **Source Data:** Copied `invocations.json` from the `mburoja-api` directly into `src/data/invocations.json`.
- **TypeScript Models:** Defined `Chapter` and `Invocation` interfaces in `src/types/data.ts` to strictly type the data.
- **Utility Functions:** Implemented helper functions in `src/lib/data.ts` to fetch chapters and invocations by ID.

## 2. State Management (Zustand)
- **Store Creation:** Built `src/store/audio.ts` using `zustand` to manage the player's state.
- **State Properties:**
  - `queue`: Array of `Invocation` objects currently loaded.
  - `nowPlayingIndex`: The index of the active dua in the queue.
  - `isPlaying`: Boolean for controlling audio playback.
- **Actions:** Methods like `play(index)`, `next()`, `previous()`, and `setQueue(items)` handle queue manipulation.

## 3. Client-Side Semantic Search (Orama)
- **Implementation:** Configured `@orama/orama` in `src/lib/search.ts`.
- **Index Schema:** Mapped `invocation_id`, `chapter_name`, `arabic`, `latin`, and `albanian` strings. 
  - *Bug Fix Note:* Explicitly renamed `id` to `invocation_id` inside the Orama schema to prevent collision with Orama's internal UUID document ID system.
- **Search Logic:** Searching executes over Latin and Albanian text natively with typo-tolerance (`tolerance: 1`).

## 4. Time-Based Routing & UI Construction
- **Homepage (`/`):** 
  - Calculates the current user time (Morning vs. Afternoon/Evening).
  - Displays a dynamic greeting ("Good Morning", "Good Afternoon", "Good Evening").
  - Automatically redirects to the `/play` route after 3 seconds, pre-loading the correct chapter queue (Chapter 1 for morning, Chapter 2 for evening).
- **Player Route (`/play`):** 
  - Uses the "Terra - Rooted Warmth" design system.
  - Features a two-pane layout: a distraction-free center focal point for reading Dzikr, and a right-sidebar for queue management and semantic search.
- **Global Audio Layout (`__root.tsx`):**
  - `<audio>` element mounted at the root layout to ensure uninterrupted playback.
  - Syncs the `zustand` queue state bidirectionally with the URL search parameters (e.g., `?queue=1,2,3&idx=0`) for stateless sharing.

## 5. Rebranding & UI Polish
- **Branding:** Rebranded the application from "Midnight Sanctuary" to "Dzikr & Dua".
- **Typing Fixes:** Ensured all TypeScript type imports use `import type { ... }` to prevent Vite ESBuild 504 errors during SSR generation and client hydration.
- **Design System:** Validated Tailwind CSS Oklch variables to map the Forest Green and Warm Cream color palette.

## 6. Production Readiness Preparation
- Created the foundation for Docker deployment. The application is capable of running via Nitro (`bun run build` followed by `bun run .output/server/index.mjs`) on default port 3000, configurable via `.env` `PORT`.
